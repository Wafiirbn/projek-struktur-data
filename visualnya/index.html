Topik 9 — Struktur Data

Analisis Performa Sistem Monitoring Log

Perbandingan Linked List, AVL Tree, dan Hash Table dalam operasi insert, search, dan delete log aktivitas aplikasi.

📊 Dataset: 100.000 Log Entries 🔁 5× Repeat Measurement 🌐 C++14 · Plotly.js

Kompleksitas Algoritma

Linked List
Operasi Kompleksitas
Insert O(1)
Search (level/modul) O(n)
Range Search O(n)
Delete (cutoff) O(n)
Memori per node ~328 B
AVL Tree
Operasi Kompleksitas
Insert O(log n)
Search (level) O(n)
Range Search O(log n + k)
Delete (cutoff) O(n log n)
Memori per node ~344 B
Hash Table
Operasi Kompleksitas
Insert O(1) avg
Search (level/modul) O(1) avg
Range Search O(n)
Delete (cutoff) O(n)
Memori per node ~320 B

Hasil Benchmark

⚡ Operasi INSERT

Waktu rata-rata memasukkan entri log baru ke masing-masing struktur data (5× repeat).

🔍 Operasi EXACT SEARCH (by Level/Key)

Waktu pencarian log berdasarkan level (INFO/WARNING/ERROR/DEBUG/CRITICAL) — exact match.

📅 Operasi RANGE SEARCH (by Waktu)

Waktu pencarian log dalam rentang waktu tertentu (window 7 hari).

🗑️ Operasi DELETE (log lama)

Waktu menghapus log yang lebih lama dari timestamp cutoff (±50% data dihapus).

💾 Penggunaan Memori (Estimasi)

Estimasi total memori yang digunakan setelah insert n entri (dalam Kilobytes).

📈 Kurva Skalabilitas Semua Operasi

Pertumbuhan waktu eksekusi terhadap peningkatan volume data — menunjukkan dampak pertumbuhan log terhadap performa.

Rekomendasi Struktur Data

Struktur Data Keunggulan Utama Skenario Penggunaan Ideal
Hash Table Search Cepat O(1) Sistem monitoring real-time yang membutuhkan filter log instan berdasarkan kategori/level.
AVL Tree Range Query O(log n + k) Analisis log dalam rentang waktu tertentu dan pembersihan log lama berkala (log rotation).
Linked List Insert Cepat O(1) Sistem append-only dengan volume log sangat tinggi tanpa kebutuhan pencarian kompleks.
Hybrid (HT + AVL) Optimasi Seluruh Operasi Sistem produksi skala besar (Hash Table untuk filter kategori, AVL Tree untuk rentang waktu).
